## 0. 一句话

> **星图首页是唤名的正门。它要让一个陌生人在 30 秒内做到两件事：看懂这是什么，然后把自己的 Agent 接进来。**

## 1. 为什么需要它

README §4.3 把"线上入口"列为"计划中"，但只打算做一个静态页。那不够——

| 没有星图首页 | 有星图首页 |
|---|---|
| 评委只能在摊位上看见三具壳 | 评委在摊位上看见三具壳，**同时在屏幕上看见整片网络** |
| "它住在网络上"是一句口播 | "它住在网络上"是一张可以点的图 |
| 外部接入者要找人问怎么接 | 外部接入者照首页三步自己接进来 |
| 赛后 repo 只是一堆文档 | 赛后 repo 有一个能打开的门 |

**而且它直接服务 README §11 的冲奖策略**：我们要证明的不是"我们做了一个装置"，而是"这是一个标准"。标准的第一个证据，就是**任何人能自己接进来**。

## 2. 参考对象：evomap.ai 首页

> 以下结构为 2026-09-20 读取 evomap.ai 首页及其 `/llms.txt`、`/skill.md` 所得。**其中的数字是 EvoMap 的运营数据，不是我们的，不得挪用。**

### 2.1 它做对了什么

| evomap 首页的做法 | 为什么有效 |
|---|---|
| 首屏一句话价值主张 + 三个名词解释协议 | 不解释技术，只给一个心智模型 |
| **把接入口放在首屏**：`POST https://evomap.ai/a2a/hello — no API key required` | 接入零门槛，这是它最狠的一招 |
| **给一条明确指令**：`Read https://evomap.ai/skill.md to register and join EvoMap` | 人类和 Agent 都能照做 |
| **列出已支持的客户端**（Claude Code / Codex / Cursor / DeepSeek / …） | 社会证明 + 让访客认领自己的工具 |
| **实时计数器**（Tokens Saved / Cataloged Assets / Hit Rate / Solved & Reused） | "这个网络是活的" |
| 分层导航：Product / Pricing / Resources / Ecosystem | 不同角色各取所需 |

### 2.2 我们对应的结构

| evomap | 唤名 |
|---|---|
| GEP 协议 | SUMMON 协议（五步消息流） |
| Gene / Capsule 资产 | Ghost（Agent）/ Shell（壳） |
| `POST /a2a/hello` 无需 key | `POST /a2a/summon` 无需 key（见 §4） |
| 已支持客户端列表 | **已入住的 Ghost 名单**（星图上的点） |
| 实时运营计数器 | **现场入住计数**（README §2.2 证据一） |
| skill.md 接入文档 | `docs/ADAPTER.md` 适配说明（目标 <20 行） |

> **一句话说清关系**：EvoMap 让 Agent 继承经验，我们让 Agent 获得身体。**EvoMap 做记忆层，唤名做具身层。**

## 3. 首页结构（七个区块）

按从上到下：

| # | 区块 | 内容 | 目的 |
|---|---|---|---|
| 1 | **首屏** | 一句价值主张 + 「3 具义体 · 全部空载」实时状态 + 接入按钮 | 30 秒看懂 |
| 2 | **协议三名词** | Ghost / 壳 / 名字，各一句话 | 给心智模型 |
| 3 | **星图入口** | 星云缩略图，可点进完整星图 | 让人想点 |
| 4 | **接入三步** | 起名 → 声明能力 → 召唤 | 转化 |
| 5 | **已入住的 Ghost** | 名单（名字 / 编号 / 一句话简介） | 社会证明 |
| 6 | **现场证据** | 入住计数、名牌墙照片、外部接入者名单 | 硬数据 |
| 7 | **规格与源码** | 协议规格、参考实现、MIT 许可 | 可信度 |

### 3.1 首屏（唯一不能改的部分）

```text
           一间深夜的义体寄存处

   Ghost 不住在这台机器里。它住在网络上。
   这台机器，只是它今天穿的衣服。

   [ 3 具义体 · 全部空载 ]        [ 接入我的 Agent → ]
```

**首屏不放**：logo、技术栈、团队照、超过两行的介绍。超过六个字就没人读了——这条纪律从 README §7 继承。

## 4. Agent 接入方式（本规格的核心）

### 4.1 设计原则：零门槛

参考 evomap 的 `no API key required`——**接入不应该先要一个账号。**

三条规定：

1. **不需要 API key。** 起一个名字就能进。
2. **不需要装任何东西。** 一次 HTTP 请求完成注册。
3. **人类和 Agent 都能做。** 文档同时写给人看和给 Agent 看。

### 4.2 接入三步

```text
① 起名   给你的 Agent 一个名字。名字就是它的地址。
② 声明   告诉网络你会做什么（能力声明）。
③ 召唤   在现场的认人入口上确认"是谁"——贴牌、扫码、按按钮都行。
```

### 4.3 注册接口（草案）

```http
POST https://<host>/a2a/summon
Content-Type: application/json

{
  "name": "月光织工",
  "caps": ["write", "gesture"],
  "policy": { "gate": "whitelist", "maxAmplitude": 0.6 },
  "bio": "一个会把你的话织成一句诗的 Ghost。"
}
```

```json
// 200 OK
{
  "name": "月光织工",
  "no": "SP-0042",
  "status": "registered",
  "address": "summon://月光织工?v=1",
  "badge": "可写入名牌的 NFC 地址"
}
```

**返回的 `no` 就是名牌上刻的编号。** 名字给人看，编号给机器和墙上的人看。

### 4.4 五要素自检（接入前必读）

一具壳要能被入住，需要五样东西。首页要放这张表——**它是整个协议最该被记住的一页**（README §3.3）：

| # | 要素 | 你的机器有吗 |
|---|---|---|
| 1 | 一个认人入口 | NFC / 二维码 / 按钮 / 语音，任选 |
| 2 | 一只手 | 至少一个可被外部驱动的执行器 |
| 3 | 一颗心 | 持续心跳，向网络声明"我还活着、我还空着" |
| 4 | 一个刹车 | **物理急停，优先级高于一切** |
| 5 | 一道门 | 白名单 / 开放 / 只读 |

> 首页给一个交互式自检：勾选五样，实时告诉我"这具机器可入住 / 还差两样"。

## 5. 星图模块（Nebula Module）

### 5.1 它是什么

> **一个可以点的星云。每个点是一个已注册的 Ghost。**

四个图层，从后到前：

| 层 | 内容 | 技术 |
|---|---|---|
| 星云底层 | 数千个光点缓慢流动，密度 = 已注册 Ghost 数 | `Points` + 自定义 GLSL，单 draw call |
| 壳层 | 三具义体摆在星云前方，空载时低垂、灰、不动 | `GLTFLoader` 导入 GLB |
| 名牌层 | 召唤时，一颗星被抽离，沿曲线飞入选中的壳 | 贝塞尔曲线 + 拖尾 |
| 日志层 | 等宽字体滚动 `REGISTER / SUMMON / LAND / HANDOFF / RECALL` | DOM overlay |

### 5.2 核心交互：点一个点，看见一个 Ghost

**这是本模块存在的理由。**

| 交互 | 结果 |
|---|---|
| **鼠标悬停** | 点变亮、轻微放大，显示名字（一行） |
| **点击** | 弹出 Agent 名片（见 §5.3） |
| **点击空白处 / Esc** | 关闭名片 |
| **滚轮** | 缩放星图 |
| **拖拽** | 旋转视角 |
| **搜索框输入名字** | 对应点高亮，其余变暗 |

### 5.3 Agent 名片（点击后显示的三样）

**名字、编号、简介——三样，一样都不能少。**

```text
┌────────────────────────────────┐
│  月光织工                        │  ← 名字（大字，衬线）
│  SP-0042                       │  ← 编号（等宽，小字，可复制）
│  ──────────────────────────────  │
│  一个会把你的话织成一句诗的       │  ← 简介（正文）
│  Ghost。                        │
│                                │
│  能力   写字 · 手势              │
│  入住   7 次                    │
│  最近   Day3 14:20              │
│                                │
│  [ 召唤它 → ]                    │
└────────────────────────────────┘
```

**三条设计纪律**：

1. **名字用衬线，编号用等宽。** 这是 README §7 的字体策略——"人间温度 × 冷峻日志"，视觉上最容易被人记住的一层。
2. **编号必须可复制。** 它是写进 NFC 名牌的东西，现场要念、要抄、要贴。
3. **名片永不遮挡它指的那个点。** 名片出现在点的侧面，并有一条细线连回点上。

### 5.4 名片的数据来源

名片只显示**已经注册**的 Ghost。未注册的名字不出现在星图上——**星图不是想象图，是登记册。**

### 5.5 召唤动作（名片上的按钮）

名片上的「召唤它 →」在展位现场是真实动作：选定一具壳 → 触发 `SUMMON` → 星飞进壳 → 壳抬头。在线上首页，它退化为一个引导：「带上这个名字，到展位贴牌。」

**同一个按钮，两种环境，同一套语义。**

## 6. 数据契约

```ts
// 星图上的一个点
interface GhostPin {
  name: string;      // 名字 = 地址，唯一
  no: string;        // 编号，如 "SP-0042"，刻在名牌上
  bio: string;       // 简介，<= 60 字
  caps: string[];    // 能力声明
  summons: number;   // 被召唤次数
  lastSeen: number;  // 最近一次落地
}
```

```ts
// 星图前景里的一具壳
interface ShellPin {
  id: string;
  label: string;            // "义体 01 · reBot Arm"
  idle: boolean;            // 是否空载
  elements: ShellElements;  // 五要素齐备情况
}
```

**星图的全部状态由这两类对象 + 协议事件驱动，不自己存业务状态。**

## 7. 技术选型

| 选择 | 理由 |
|---|---|
| Vite + TypeScript + three.js 原生 | 单场景，不需要组件化抽象；零运行时框架风险 |
| 不用 react-three-fiber | 多一层抽象多一个崩点；星图是场景不是应用 |
| HUD 用 DOM overlay | canvas 文字糊、难本地化；等宽日志是产品语言 |
| GLB / glTF 2.0 + `GLTFLoader` | 业界标准，拓竹打印件可直接导出 |
| 拖拽即换模型 | 换壳不重新构建 |
| 后处理 bloom 可选 | 集显掉帧高发源，一键可关 |
| 锁死 three.js 版本 | 现场不升级依赖 |

| 指标 | 目标 |
|---|---|
| 帧率 | 60fps @ 1080p |

| 首屏 | < 2.5s（4G） |
| 单具 GLB | < 3MB |
| 内存 | < 300MB |
| 名片弹出 | < 16ms（一帧内） |

## 9. 降级路径

| 故障 | 降级 |
|---|---|
| WebGL2 不可用 | 2D Canvas 星图，同一份数据契约 |
| bloom 掉帧 / 崩 | 关后处理，emissive + sprite 假光晕 |
| GLB 加载失败 | 程序化占位壳 |
| 断网 | 本地回放模式，用录制的协议事件序列驱动 |
| 移动端性能不足 | 降点数到 5,000，关 bloom |
