# 唤名 · SUMMON

> **一句话**：任何 Agent 只要在网络上有一个名字，就能住进任何装有接驳模块的机器里。
>
> **A Ghost is reachable by name, and any body that answers to names can host it.**

- 赛事：EvoTavern 进化酒馆黑客松 · 深圳站（2026-09-21 ~ 09-24）
- 赛道：Track 01 具身与穿戴硬件 CYBERBODY（Seeed 出题）
- 现场参考实现：**三具义体**
- 版本：v0.4 · 2026-09-19（本版修订：输入层抽象化，NFC 名牌为主路径）

---

## 一、我们要做的事

原本我们做的是一个装置：一台低垂着头的机械臂，等一个人来住。现在把它往前推一步——

**我们做的是一套协议，让"任何一个 Ghost 可以落进任何一具身体"。**

拆成两半：

| 组成 | 侧 | 是什么 | 谁写 |
|---|---|---|---|
| **Ghost 适配器** GHOST ADAPTER | 网络侧（软件） | 任何 Agent 接入后获得一个**名字**（地址），并声明自己能做什么 | 协议提供，Agent 作者填 3 个字段 |
| **Shell 适配器** SHELL ADAPTER | 物理侧（硬件 + 软件） | 任何机器装上它，就成为一具**可被召唤的壳** | 协议提供，机器主人接 5 根线 |

中间那条协议管一件事：**名字即地址，唤名即连接。**

---

## 二、为什么这是升级，不是加法

| | 装置（上一版） | 协议（本版） |
|---|---|---|
| 一具壳能装谁 | 只有我们自己的 Agent | **任何接入网络的 Agent** |
| 一台机器能不能被入住 | 只有这一台机械臂 | **任何装了接驳模块的东西** |
| 别人能不能参与 | 不能 | **能，其他队伍接入即成为网络的一部分** |
| 有没有网络效应 | 没有 | **有：接入的 Ghost 越多、壳越多，两边都更值钱** |
| 能不能回答"商业价值" | 勉强（讲场景） | **能（讲标准）** |
| 评委会怎么归类 | "一个做得很好的装置" | **"一个可能成为标准的东西"** |

**最后一行是关键。** 全场冠军评的是「完成度、突破性、真实价值」，而现场一定会有很多做得漂亮的装置。**装置的天花板是赛道冠军；标准才有资格去碰全场冠军。**

## 三、核心机制：名字就是地址

一段完整的会话只有五步。请把动词记住，全队统一口径。

| 步骤 | 动词 | 发生什么 |
|---|---|---|
| 1 | **注册** Register | Agent 作者给 Agent 起一个**名字**，注册进网络。名字是它唯一的地址 |
| 2 | **召唤** Summon | 在现场的某个**认人入口**上确认"是谁"。可以是一下触碰、一句喊话、一次扫码 |
| 3 | **落地** Land | 网络按名字找到 Agent，建立连接。**你选择的哪一具壳**抬起头 |
| 4 | **交接** Handoff | 会话有时限，到点自动断开。壳回到空的状态 |
| 5 | **回流** Recall | 这次会话跑出来的经验，结构化写回网络，成为下一位可继承的东西 |

### 一句话定调（路演必须有这句）

> **「Ghost 不住在这台机器里。它住在网络上。这台机器，只是它今天穿的衣服。」**
>
> GHOSTS LIVE ON THE NETWORK. THE SHELL IS JUST WHAT THEY WEAR TODAY.

这一句同时解决三个问题：

1. 补上了"人走了以后 Ghost 去哪了"的漏洞——**Agent 常驻网络，召唤只是建立连接，不是搬运**
2. 让"随时都能到"变成真的——**明天再来，它还在**
3. 说出了《攻壳机动队》的原设定——**Ghost 可以更换义体，义体只是壳，Ghost 可以潜入网络**

## 四、输入层：怎么认人（本版最重要的修订）

### 4.1 一个被我们之前搞错的设计

上一版的协议把第一要素写成了「**一只耳朵：远场拾音 + 声源定位**」。

**这是一个抽象层级的错误。** 它把整条协议绑死在"语音"这一种技术上，导致：
- 一具机器要想"可入住"，必须配一整套声学硬件（贵、难、要抢）
- 环境一吵就失败（游园会现场几十个摊位同时在说话）
- 延迟天然做不到最短（要等你把话说完）
- 一具只需要"被碰一下"就能工作的壳，被我们用语音挡住了

**正确的抽象应该是：**

> **要素一不是一个麦克风，而是一个"认人入口"（Identity Gate）。**
> 只要能确认"站在这里的这个人是谁"，用什么都行。技术选型是**壳的自由**，不是协议的规定。

这一点想清楚之后，协议才真正成立——因为它从此**不绑定任何输入方式**，一块贴了二维码的屏、一个按钮、一枚 NFC 牌，都能成为一具合格的壳。

### 4.2 三种认人入口的对比

| | **NFC 名牌**（主路径） | 语音唤名 | 二维码 |
|---|---|---|---|
| **延迟** | **10–50ms**（读卡） | 300–800ms（还要等静音期防误触） | 100–300ms（对焦 + 解码） |
| **靠不靠环境** | **完全不受影响** | 受噪声影响极大 | 需要光线和对焦 |
| **会不会被抢** | **不会，牌在你手上** | 会被别人听到 | 会被别人拍下来 |
| **需要什么硬件** | NFC 读卡器（几块钱） | 远场声阵列（贵、要抢） | 摄像头（一般已有） |
| **隐私** | **不涉及任何采集** | 需要收音，有争议 | 不涉及 |
| **仪式感** | 中（贴一下） | **高**（喊一声它就醒） | 低 |
| **失败率** | **极低** | 高（现场太吵） | 中 |

**结论：NFC 做主路径。语音保留为"高光时刻"的可选演示，不作为协议的一部分。**

### 4.3 名牌：一枚实体的牌，才是最好的承认

不要贴手机。**贴手机是一个功能，贴一枚牌是一个仪式。**

**设计：**

- 入住时，你拿到一枚**实体的名牌**——大约 5×8cm，用**拓竹 A1 打印**，嵌一枚 NFC 标签
- 牌上刻着你的**名字**（那个随机短语）和编号
- 想召唤时，**把牌贴到任意一具壳的胸口**
- 那一具壳抬起头——**你的 Ghost 进了你选的那具身体**

**这枚牌一次性解决了六件事：**

| 解决了什么 | 怎么解决的 |
|---|---|
| **延迟** | 触碰即读，10–50ms，没有等待 |
| **防抢** | 牌在你手上。听不到、拍不到、拿不走 |
| **隐私** | 全程不收音、不采集 |
| **仪式感** | 贴上 = 把 Ghost 交付给这具身体。这是一个可以被围观的物理动作 |
| **传播** | 一枚实体牌，可拍照、可发小红书、可带走 |
| **社会证明** | 墙上一排排名牌 = "已经有多少人住过这里"，比任何口头说服都硬 |

而且它呼应了设定：**在《攻壳机动队》的世界里，身份是靠凭证确认的。** 一枚名牌，比一句口令更像那个世界里的东西。

### 4.4 语音还留不留

留，但**降级为可选的第二入口**，用法只有一种：**当有人想看"魔法"的时候。**

- 平时走 NFC：快、稳、不失败
- 遇到重要评委、或者气氛对了的时候，可以说：「**您也可以不碰它——直接喊它的名字试试。**」

**这叫"两个入口，一条协议"。** 而且这恰好证明了协议的第一要素是"认人入口"而不是"麦克风"——**同一具壳，两种认人方式，产生完全一样的结果。**

## 五、延迟预算（把"最快"算清楚）

现场的一切都要快。下面是两条路径的实际延迟拆解。

| 环节 | 语音路径 | **NFC 路径** |
|---|---|---|
| 输入捕获 | 300–800ms（要等静音期防误触） | **10–50ms** |
| 身份确认 | 50–200ms（关键词匹配） | **≈0ms**（卡的 ID 本身就是身份） |
| 名字 → Agent 解析 | 100–300ms（网络查询） | **<10ms**（缓存命中） |
| 建立会话 | 200–800ms（拉起 Agent） | **50–150ms**（预热连接池） |
| 动作起手 | 100ms | 100ms |
| **合计** | **约 1–2.5 秒** | **约 200–400ms** |

**快了大约 5 倍。** 但真正要做的不是"优化到 200ms"，而是让**感官延迟归零**。三个关键手法：

### 手法一：把地址直接写进卡里

不要在卡里存一个 ID 再去查表。**直接把地址写进 NFC 标签**：

```
summon://<name>?v=1
```

读卡即得地址，省掉一次网络往返。这一步把身份确认压到接近 0。

### 手法二：常驻会话池（最有效的一招）

**不要把 Agent 会话当成"用的时候再启动"。** 在机器端维护一个热连接池：

- 最近 N 个活跃名字的 Agent 会话**保持热着**（这就解释了为什么要用云主机跑常驻进程）
- 触碰到热名字 → 直接接管，**<100ms**
- 触碰到冷名字 → 回源建立，约 300ms

### 手法三：动作与连接并行（让延迟消失）

**这是最关键的一招：不要等连接完成再开始动。**

- 触碰的一瞬间，壳**立刻开始"抬头"这个动作**——这个动作**不需要 Ghost 也能做**
- 抬头大约需要 300–400ms，**连接的建立恰好在这个窗口里完成**
- 等它抬起头、亮起来的时候，Ghost 已经在了

**用户感知的延迟 = 0。** 因为他的眼睛从头到尾都没有等待过。

> 这一招的原理和做 UI 一样：**先给反馈，再干真活。** 谁先把"回应"给出去，谁就不卡。

## 六、可入住标准（协议的核心）

一具机器要能被 Ghost 入住，只需要五样东西。**这是整个协议最该被记住的一页。**

| # | 要素 | 要求 | 为什么必须有 |
|---|---|---|---|
| 1 | **一个认人入口** | 任何一种能确认"你是谁"的方式：NFC、二维码、按钮、语音……**技术由壳自己选** | 没有它，就没有"召唤"这个动作。**注意：是"认人"，不是"听声"** |
| 2 | **一只手** | 至少一个可被外部驱动的执行器（舵机、电机、屏幕、灯、音箱都算） | 没有它，Ghost 进来也做不了任何事 |
| 3 | **一颗心** | 持续心跳，向网络声明"我还活着、我还空着" | 网络需要知道哪些壳现在可用，才能把 Ghost 落地过去 |
| 4 | **一个刹车** | **物理急停，优先级高于一切** | 这是硬件。任何人都必须能在 0.5 秒内切断所有外部控制 |
| 5 | **一道门** | 授权模式：白名单 / 开放 / 只读 | 机器主人的机器，不能谁都能开 |

> **任一具机器，只要凑齐这五样，就"可入住"。**
> 少的那些不算壳——它只是一台电器。

**落地示例**（说明这个标准的门槛有多低）：

| 机器 | 认人入口 | 手 | 心 | 刹车 | 门 | 可入住？ |
|---|---|---|---|---|---|---|
| reBot Arm 六轴机械臂 | NFC 名牌 | 6 关节 + 夹爪 | 有 | 物理断电 | 白名单 | ✅ |
| 舵机自制小体 | NFC 名牌 | 1–4 舵机 | 有 | 物理断电 | 开放 | ✅ |
| 一盏智能台灯 | NFC 名牌 | 亮度 / 色温 | 有 | 拔电 | 开放 | ✅ |
| 一台投影仪 | 二维码 | 画面 | 有 | 拔电 | 白名单 | ✅ |
| 一块屏 | 二维码 | 显示 | 有 | 拔电 | 白名单 | ✅ |

**注意最后三行。** 这说明了协议的关键性质：**接驳模块接上什么，什么就变成一具壳。** 不是只有机器人才能被入住。

## 七、现场参考实现：三具义体

展台上摆三具义体（一具 reBot Arm + 两具用总线舵机驱动板与打印件自制的小体），分散在摊位左、中、右，**全都低垂着头、全部空载**。

**演示流程：**

1. 评委走近，拿到一枚刻着他名字的**名牌**
2. 他把牌**贴到任意一具壳的胸口**——是他自己选的那一具
3. 那一具壳**立刻开始抬头**（第 0 毫秒就动了）
4. 250ms 后它完全点亮——**他的 Ghost 已经在了**
5. 壳替他完成一件事（写一笔 / 做一个手势），然后回到待机
6. 屏幕上出现：**「名字已写入网络。明天带同一枚牌回来，它还在。」**

**为什么这个 demo 值钱：**

- **触碰即响应，眼睛看不到等待**——评委按下到抬头是连续的，中间没有"加载中"
- **"我选哪具身体"比"最近的那具"更好**——选择权在他手上，这更接近原作的设定，戏剧性也更强
- **可重复几十次不崩**——NFC 不受噪声影响，这是它最大的工程收益
- **一枚实体牌**——可带走、可拍照、可发小红书，同时墙上一排排名牌就是社会证明

**语音版（可选的高光演示）**：在气氛好的时候才打开。同一具壳、同一个名字、同一个结果——**用两种方式证明"认人入口"是可替换的**。

## 八、安全与授权（必须先说，不能等评委问）

这是这套协议最大的风险面，也是最能体现"我们真的想过"的地方。**路演时主动讲。**

### 8.1 威胁与对策

| 威胁 | 具体场景 | 对策 |
|---|---|---|
| **抢名** | 别人冒用你的身份召唤你的 Agent | **NFC 主路径天然免疫**——牌在你手上，听不到、拍不到、拿不走。语音路径才需要"名字 + 方位"双因子 |
| **无主占用** | 有人长时间占着一具壳不放 | 会话**有时限**（默认 60 秒），到点自动断开并交接 |
| **无人时的物理风险** | 过夜黑客松，机器被远程驱动 | ① **物理急停**，任何人都能按 ② 无人值守自动断连（10 分钟无人在场则拒绝所有会话）③ 切断电源即断连，不依赖软件 |
| **隐私** | 会不会录下别人说话 | NFC 路径**完全不涉及音频采集**。语音路径**只做本地关键词匹配，不留存音频**，不匹配的语音直接丢弃 |
| **算力与 Token 归属** | 别人召唤我的 Agent，烧的是谁的 Token | 协议写清楚：**谁注册谁承担**。召唤方只发请求，推理成本记在 Agent 所有者账上 |
| **恶意动作** | 一个坏 Agent 住进别人的机器乱动 | ① 门的白名单 ② **动作幅度上限**由壳的主人设定 ③ 只读模式下 Ghost 只能感知不能驱动 |

### 8.2 三条不可让步的红线

> 1. **刹车优先于一切。** 物理急停不需要经过网络、不需要经过软件、不需要任何人同意。
> 2. **机器主人的授权不可被绕过。** 协议不提供任何"强制入住"的能力，永远。
> 3. **没有录音留存。** 耳朵只认名字，不记事。

这三条写进协议正文，不是可选项。**一个安全的协议才有资格谈生态。**

## 十、现场怎么让别人接入（证明力最大的一件事）

**关键动作：在 Day2–Day3 拉到 1–2 支其他队伍，成为"首个外部接入者"。**

1. **做一个 15 行的适配示例**，任何 Agent 作者照着改就能接入（越短越好，最好当场能跑通）
2. **把接驳模块做成可借出的**：任何队借走一个，他们那台机器就变成网络里的一具壳
3. **在现场立一块公开的墙**：挂上所有已注册的名字牌（**带他们的队名**）
4. **路演时指着墙说**：「这是 XX 队、XX 队的 Agent。它们现在住进了我们网络里的壳。」

**这一件事的证明力，超过任何 PPT。**

**注意分寸**：不要说"我们的生态"，我们没有生态。说「**我们今天在现场验证了 2 个外部接入者**」。具体、可验证、不吹。

## 十一、商业价值（投资人会问）

### 11.1 我们收什么

- **协议开源，适配器免费**——不靠卖软件赚钱
- 收的是**网络侧**：名字注册、会话路由、经验回流 —— **这恰好就是 EvoMap 现在的位置**
- 所以我们和 EvoMap 是同一层里互补的两半，不是抢生意

### 11.2 落地场景（按付费意愿排序）

| 场景 | 为什么需要 | 现在缺什么 |
|---|---|---|
| **展厅 / 博物馆** | 互动装置最贵的问题不是不炫，是**它不记得人**。所以每个游客都是新游客，复访率是零 | 缺"身份层"：装置认不出回头客 |
| **连锁门店** | 同一套机器人硬件，换个 Agent 就换个角色。白天导购，晚上巡检 | 缺"寻址层"：硬件和 Agent 绑死在一起 |
| **养老 / 康复** | 老人需要的不是一台设备，是**同一个人**天天在 | 缺"存续层"：换设备就换人格 |
| **教育 / 教具** | 一台机器，每个孩子可以放进自己的 Agent | 缺"多租户" |
| **共享设备** | 一台机器被多人分时使用，各自带自己的 Ghost | 缺"接驳标准" |

**注意 NFC 在这里的额外优势**：名牌本身就是**会员卡**。展厅、门店、乐园要发卡这件事，我们顺手替他们做了——**而且这张卡能让设备认出人。**

### 11.3 一句话

> **今天所有做 Agent 的公司都在抢"那个更聪明的脑子"。我们在做的是"任何脑子都能用的那具身体"——以及那套让身体认得出脑子的命名规则。**

## 十二、45 小时落地路径

**先说结论**：45 小时做不出生态。**做得出的是一份协议草案 + 一个跑通的参考实现 + 若干外部接入者。**

> 我们不是来发布平台的。**我们是把 spec 写出来，并在现场用三具壳验证它。**

### 12.1 功能分层

| 层级 | 内容 |
|---|---|
| **P0 必须** | NFC 读卡打通 · 单具壳 + 召唤 + 网络寻址跑通 · 名牌打印（至少 35 枚）· 姿态编排（低头 / 抬头 / 做一件事）· **物理急停** · 毫秒级响应与动作并行 |
| **P1 有余力** | 第二、三具自制壳 · 常驻会话池（压延迟）· 经验回流 · 外部接入者的适配示例 · 语音作为可选第二入口 |
| **P2 不做** | 多租户计费、权限系统、Web 控制台、协议文档站、SDK 多语言版本 |

### 12.2 倒排时间表

| 时间 | 做什么 |
|---|---|
| Day1 20:00–24:00 | 定赛道 · **NFC 读卡先打通**（最大未知项，最先验证）· 协议 spec 第一版 |
| Day2 00:00–12:00 | 网络侧：名字注册 + 按名字检索 Agent + 建立连接。**先做出"触碰 → 抬头"的最快路径** |
| Day2 12:00–24:00 | **▲ 关键检查点：单具壳端到端跑通**（碰牌 → 抬头 → 做一件事 → 回待机） |
| Day3 00:00–12:00 | 工艺加固：急停、授权模式、会话时限、失败降级。**测 50 次触碰的成功率** |
| Day3 12:00–20:00 | 第二、三具自制壳。Open Hour 在真实观众身上压测排队与并发 |
| Day3 20:00–D4 04:00 | **去拉外部接入者**（最容易漏、但证明力最大）· 名牌批量打印 · 演示视频 |
| Day4 04:00–11:00 | 封板前 50 连彩排 · 演示版本冻结 |

### 12.3 唯一一个硬决策点

> **Day2 24:00。** 如果"触碰 → 抬头 → 完成一件事"这条链路还没跑通，**立刻砍掉第二、三具壳**，只做单具壳。
> 单具壳的故事仍然完整：一枚牌，一具壳，碰一下它就醒。

## 十三、路演怎么说

### 13.1 四分钟结构

| 时间 | 环节 | 关键台词 |
|---|---|---|
| 0:00–0:20 | **静默** | 不说话。侧身让开，让评委看那三具低着头的壳。**他一开口就毁了** |
| 0:20–0:50 | **定调** | 「它不是坏的。它是一具空载的义体——里面没有 Ghost。」「我们试过给它写一个灵魂，写不出来。所以换了个办法：**让它等一个愿意住进来的人。**」 |
| 0:50–1:40 | **让他动手** | 递给他一枚名牌：「**这是您的名字。贴到您想让它进的那一具上。**」——他贴上去，壳立刻抬头，中间没有等待 |
| 1:40–2:50 | **讲协议** | 「Ghost 不住在机器里，**它住在网络上，机器只是它今天穿的衣服。**而且我们刻意没把协议绑在语音上——**只要一个壳能认出人，它就能被入住。**贴卡也行，扫码也行，喊名字也行。」 |
| 2:50–3:30 | **主动降权（胜负手）** | 「您可能觉得这就是机械臂做动作。**我可以把它换成一块屏、一盏灯、一个投影仪——协议一个字都不用改。** 几十支队在让机械臂抓东西，我们让它认得出人。」 |
| 3:30–4:00 | **利他收尾** | 「不管您今天住不住进来，这个思路您可以带走：**做 AI 产品的时候，别急着给它的灵魂下定义。先给它一具身体，看谁会来。**」 |

### 13.2 三个短版本（现场更常用）

- **90 秒版**：直接用别人的痕迹讲——「这枚牌是 20 分钟前一位选手留下的，他的 Ghost 现在还在壳里。」
- **15 秒版**：「**它没有灵魂。直到你贴上你的名字。**」
- **回访版**（第二次路过，全场最值钱的 5 秒）：壳认出他，你只说——「**欢迎回来。您上次让它写的那一笔，正在教第 7 个人。**」然后闭嘴。

### 13.3 提前布局

Day2 导师巡场或 Day3 嘉宾分享之后，**请一位有分量的导师先住进来**。之后每来一位评委你都能说：

> 「这枚是 **XX 老师**刚才留下的。他的 Ghost 现在还在壳里，正在帮下一个人。」

### 13.4 问答预判（最凶的六条）

| 问题 | 怎么答 |
|---|---|
| **这不就是机械臂做动作吗？** | 「换成一块屏、一盏灯、一个投影仪，协议一个字不用改。**壳不是重点，认得出人才是。**」 |
| **为什么不用语音？** | 「语音我们做了，但只作为可选的第二入口。**现场太吵，语音会失败，我不接受我的 demo 会因为别人在隔壁喊而失败。** 而且一具壳该怎么认人，应该由造壳的人决定，不该由协议规定。」 |
| **断网了呢？** | 诚实说：「**断网它就真的是一具空载的义体**——因为 Ghost 在网上。这既是它的设定，也是它的限制。」 |
| **怎么识别身份？采集了什么？** | 「**NFC 路径完全不采集任何东西。** 牌是一次性生成的，壳只记住『这枚牌来过』。不收音、不拍照、不存个人信息。」 |
| **商业价值？** | 「展厅的互动装置最贵的问题不是不炫，是**它不记得人**。而且**名牌本身就是会员卡**——展厅和门店本来就要发卡，我们顺手让那张卡能让设备认出人。」 |
| **EvoMap 是真用了还是贴牌？** | 「现场可以看写入日志。」**然后诚实补一句**：「演示库里有一部分是预置的种子经验用来保证稳定，**但真实写入和读取是真跑的。**」 |

> 诚实回答比漂亮回答得分高。这条纪律来自我们此前记录的教训：**不要声称用了没真用的东西。**

## 十四、风险与降级

| # | 风险 | 降级 / 兜底 |
|---|---|---|
| R1 | **NFC 读卡器拿不到 / 驱动不通** | 立刻切二维码（延迟 100–300ms，可接受）。**这也是协议化的好处：换个认人入口，故事不变** |
| R2 | 抢不到 reBot Arm | 总线舵机驱动板 + 打印件自制壳，更符合"尚未被定义的消费电子" |
| R3 | 只抢到一台设备 | 砍掉多具壳，只做单具。故事仍然完整 |
| R4 | 名牌打印排不上队 | 纸质卡 + 现成 NFC 贴纸替代。**牌是道具，不是机制** |
| R5 | 网络抖动 / EvoMap 不稳 | 本地镜像 + 写入重试。口播诚实说明「种子 + 真实读写」 |
| R6 | 触碰失败（读卡距离/角度） | 卡位做成凹槽，或加一枚物理按钮做兜底。**要求 50 次触碰成功率 100%** |
| R7 | 围观人数过多、排队 | 并发会话队列，大屏同时显示多个 Ghost 的状态 |
| R8 | 被问"你们的生态有几个接入者" | 不要说生态。说「**今天在现场验证了 N 个外部接入者**」 |

## 十五、名词表（全队统一口径，不许混用）

| 词 | 英文 | 定义 | 不许说成 |
|---|---|---|---|
| **Ghost** | Ghost | 住在网络上的 Agent | 「机器人里的人工智能」 |
| **壳 / Shell** | Shell | 接上接驳模块、可被入住的机器 | 「设备」「硬件」 |
| **名字** | Name | Ghost 的地址 | 「激活词」「指令」「口令」 |
| **名牌** | Name Tag | 刻着名字的实体凭证（NFC） | 「工牌」「会员卡」 |
| **认人入口** | Identity Gate | 壳用哪种方式确认你是谁（NFC / 二维码 / 语音 / 按钮） | 「读卡器」「麦克风」 |
| **召唤** | Summon | 确认身份、建立连接这个动作 | 「语音控制」「下达命令」 |
| **落地** | Land | Ghost 接进某具壳 | 「下载」「安装」「导入」 |
| **交接** | Handoff | 会话结束，壳回到空的状态 | 「关闭」「退出」 |
| **回流** | Recall | 会话经验写回网络 | 「上传日志」 |
| **接驳模块** | Dock | 装到机器上让它成为壳的那个硬件 | 「网关」「控制板」 |

**为什么较真这个**：混用词汇会让评委觉得你在含糊其辞。**全程只用一套词，设定才立得住。**

## 十六、待确认的事

1. **NFC 读卡器从哪来**——现场设备清单里没有，需要自己带或去借。**这是 P0 的前置，Day1 就要确认**
2. 拓竹 A1 能否在 45 小时内打出 35 枚名牌？（如果不行，先打 10 枚 + 其余用纸质卡）
3. EvoMap 是否开放**按 key 检索 Agent** 的接口？如果只能检索"经验"不能检索"Agent"，协议第一条要改写
4. 现场设备的**预约规则**：排队、抽签还是先到先得？影响 Day1 晚上行动
5. 是否允许把接驳模块**借给其他队伍**？如需报备，Day1 就去问
6. 过夜时段的**用电与设备看管**规则——急停与无人值守策略要按现场实际调整

## 附二：这一版改了什么

| 改动 | 原因 |
|---|---|
| 要素一从「一只耳朵（拾音+声源定位）」改为「**一个认人入口**」 | 原设计把协议绑死在语音上，是抽象层级错误 |
| 主路径从语音改为 **NFC 名牌** | 延迟快约 5 倍、不受噪声影响、天然防抢、不涉及隐私采集 |
| 新增**名牌**这个实体道具 | 一枚牌同时解决延迟、防抢、隐私、仪式感、传播、社会证明六件事 |
| 新增**延迟预算**与三个优化手法 | 把"最快"从口号变成可执行的方案 |
| 「离你最近的那具」改为「**你选的那具**」 | 选择权在评委手上，戏剧性更强，更接近原作设定 |
| 远场声阵列从必需降为可选 | 诚实调整——NFC 路径不需要它，不硬蹭硬件 |
