义体 SHELL · 机制升级

唤醒词，是 Ghost 的地址A WAKE WORD IS AN ADDRESS, NOT A COMMAND

你的想法一句话就能概括：喊一个词，机械臂就去 EvoMap 把对应的 Agent 拉进来。这不是"再加一个功能"——它替换掉了我原方案里最弱的一环（靠一张入职牌上的随机码来认人，既取巧又没技术含量），而且顺手摸到了《攻壳机动队》最核心的设定。

01

为什么这是升级，而不是加法

原方案你的方案
怎么认人扫入职牌上的一次性随机码喊一个词——不带任何东西
麦阵的角色装饰。只是"入住的另一个入口"核心机制。没有麦阵，"召唤"不成立
Agent 住在哪含糊。听起来像"配置被加载进机械臂"明确住在 EvoMap 上，机械臂只是它临时穿的衣服
对 EvoMap 的用法"检索经验"——被动查询"Agent 可寻址"——把 Agent 本身存进网络，任何人可召唤
科幻感中高。一声召唤，死寂的机械从网络里接回一个灵魂
它命中了一个你没提但很关键的点

EvoMap 的命题是「让 Agent 搜索、继承并调用网络中已经验证的经验」。你的机制是它的加强版——不只是"调用经验"，而是"调用 Agent 本身"。经验是被动数据，Agent 是主动的。这个差别在评委耳朵里是听得出来的。

02

最重要的重构：Ghost 根本不在壳里

这是你的 idea 里最有价值的一句话，但它需要被说出来、被架构支撑、被路演讲清楚。

THE ONE LINE
「Ghost 不住在这台机器里。
它住在网络上。这台机器，只是它今天穿的衣服。」
GHOSTS LIVE ON THE NETWORK. THE SHELL IS JUST WHAT THEY WEAR TODAY.

之前"义体"的说法有个漏洞：如果 Ghost 进了壳里，那评委走了以后 Ghost 去哪了？"随时都能到"就成了空话。

你的机制把这个漏洞补上了，而且是靠"承认它不在壳里"补上的。

  • Agent（Ghost）常驻在 EvoMap 上，有自己的地址——地址就是那个唤醒词
  • 机械臂（Shell）只是一具公共义体，它自己不拥有任何 Ghost，它只是一个能装 Ghost 的身体
  • 唤醒词生效的那一刻，不是"把 Ghost 搬进来"，而是给它俩建立了一条连接
  • 所以你离开会场之后，壳回到空的状态——但你的 Ghost 还在网上，明天喊同一个词，它还在

这就是《攻壳机动队》的原设定：Ghost 可以更换义体，义体是壳，Ghost 可以潜入网络。你不是在借用一个科幻外壳——你是把原作最标志性的机制做成了可运行的东西。

03

演示形态：多台壳 + 声源定位 = 「Ghost 落地」

这是你这个机制真正炸的地方。单台壳只能做到"召唤"，多台壳能做出"Ghost 在网络里游荡，落到离你最近的那具身体里"。

Demo：三具壳，一声喊

展台上摆三具壳（一台 reBot Arm + 两台用总线舵机驱动板 + 打印件做的小体），分散在摊位左中右，全都低垂着头、全部待机。

评委站在摊位左侧，喊出他的唤醒词 → 远场麦阵通过声源定位算出他在左边 → 最左边那具壳抬起头，另外两具纹丝不动。他的 Ghost 落在了离他最近的身体里。

STEP 01
待机
三具壳都低垂着头。屏幕上写「3 具义体 · 在线」。
STEP 02
喊词
评委喊出他的唤醒词，比如「沙漠里的第九颗糖」。
STEP 03
定位
麦阵锁定声源：方位角 左侧 30°。判定"Ghost 应该落在最近的壳"。
STEP 04
寻址
拿这个词去 EvoMap 检索，命中一个 Agent。找到了。
STEP 05
落地
左侧那具壳抬头，另两具不动。Ghost 落进了离他最近的身体。

为什么这个 demo 值钱：它同时展示了三件独立的技术，但观众只看到"一声喊，离我最近的那个醒了"——零解释成本。而且它是可以被反复触发几十次的（每个评委都喊一次自己的词），完全符合游园会流动评审的节奏。

降级：如果只抢到一台壳，就砍掉"落地路由"，只做"召唤"。故事仍然完整——单台壳的版本已经比原方案强。

04

三个必须解决的问题（不解决会翻车）

问题一：唤醒词是公开的，别人听到了就能召唤你的 Agent

这是你这套机制唯一致命的漏洞。但先别急着补——它其实是双面的。

解法怎么做代价
A · 一次性私密词推荐主推 入住时系统随机生成一个短语（「沙漠里的第九颗糖」），只写在你自己的凭证卡上。别人不知道，就召唤不了。 零成本。而且短语本身很有仪式感
B · 词 + 方位双因子推荐叠加 不只是词对，还要你站在当初入住的那个位置（麦阵记得你从哪个方位来的）。 需要声源定位稳定，但正好复用"落地路由"的能力
C · 声纹 词 + 说话人声纹双因子。 不推荐 45 小时里声纹识别的鲁棒性风险太高
D · 公开客座 Ghost保留一个 故意留一个公开的唤醒词（比如 EvoX 官方 Agent，或某位导师的 Agent），任何人都能召唤它。 把它做成"公共义体"的现场演示：网络里的 Ghost 可以被任何人调用

推荐组合：A + B 做主路径（专属感），D 留一个公开席位做概念演示。这样既保住了评委的"这是我的 Agent"的专属体验，又完整表达了"Ghost 在网络里可被任何人寻址"的开放语义——两边的好处都拿到了。

问题二：语义必须自洽，不能自相矛盾

一个很容易翻车的地方：如果你一会儿说"Ghost 住进了壳里"，一会儿又说"Ghost 在网上"，评委就会觉得你在含糊其辞。所以全程统一口径，只用一个说法：

  • ✅ 「它接上了你的 Ghost」／「你的 Ghost 落进了这具壳」——连接/落地的语义
  • ❌ 「它把你的 Agent 下载进来了」／「Agent 存在机械臂里」——搬运/存储的语义

前者说得通：网络上有一个 Agent，壳是执行器，唤醒是建立连接。后者说不通：装不下、也留不住。

问题三：45 小时做得完吗

做得完，而且比原方案更简单——因为你砍掉了"识别随机码"那一整套东西，换成了关键词匹配（更简单），而且关键词匹配正好是麦阵的原生能力。

模块工时难度
麦阵关键词唤醒（唤醒词识别）6–8h麦阵原生能力
声源定位 → 路由到最近的壳6–10h中，需标定
EvoMap 按词检索 Agent + 建立连接5h标准操作

决策建议：Day2 24:00 前先跑通「单台壳 + 唤醒词 + EvoMap 寻址」这条最小路径。多台壳和声源路由是 P1——有余力才做，因为它虽然最炸，但机械结构调试会吃光你的时间。

路演怎么讲（这段替掉原稿里的 C、D 两段）

「它不是语音助手。那个词不是命令，是地址。」

「您的 Agent 从来不在这个机械臂里。它住在 EvoMap 上。这具壳只是它今天穿的衣服。」

（把入住牌递给他，上面印着一个随机短语）「这是您的地址。您喊一声试试。」

（他喊出来 → 离他最近的那具壳抬头）

「它听见了。而且它知道您站在哪——所以是离您最近的那一具醒了。」

「这就是《攻壳机动队》：Ghost 在网上，壳是可以换的。您走出这个会场之后，这具壳会回到空的状态 —— 但您的 Ghost 还在网上。明天喊同一个词，它还在。」

新增的问答预判

会问什么怎么答
唤醒词被别人听到了怎么办？「词是一次性随机生成的，只写在他自己的凭证上；而且还要他站在当初入住的方位上，方位也是双因子的一部分。」
那你们的壳不就成了公共的了？「对，这就是重点。壳是公共义体，Ghost 才是私有的。我们留了一个公开席位给官方 Agent，任何人都能召唤——你随时可以试。」
和语音助手有什么区别？「语音助手的词是命令，执行完就没了。我们的词是地址，它指向一个持续存在的东西。区别是：明天喊同一个词，它记得你昨天来过。」
断网了呢？诚实说：「断网它就真的是一具空载的义体——因为 Ghost 在网上。这既是它的设定，也是它的限制。」（这个诚实的回答反而会加分，因为它证明设定是自洽的）
