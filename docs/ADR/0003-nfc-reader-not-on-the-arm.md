# 0003. NFC 读卡器不挂在机械臂上

- 日期：2026-09-21
- 状态：Accepted
- 影响面：`docs/HARDWARE.md` 的「认人入口」；`docs/PLAN.md` 把 NFC 列入 P1 拉伸项

## 背景

Passport 的 NFC 是**被动 NTAG213**，只能被读、不能读别人，所以"贴牌召唤"必须外加读卡器。
第一个直觉是把读卡器装到机械臂末端——牌贴上去，臂读卡，然后召唤。

但协议的五要素里，"认人入口"与"手"是**两个独立要素**（`docs/PROTOCOL.md` §3.3）。
把它们焊在一起，等于把协议要消除的耦合又造了回来。

## 决策

读卡器是**固定接驳台**，接现场电脑，独立于任何执行器。
机械臂只承担"手"的角色。

两条认人入口路径：固定接驳台（USB 读卡器，10–50ms）为主路径；
NTAG213 名牌 + 游客手机碰一下打开星图网页为兜底，不需要额外硬件。

名牌写 `summon://<agent_id>?v=1`，但按 `docs/PROTOCOL.md` §1，
**它只是寻址线索，不是凭证**——贴牌只能选定一个已获授权的 Agent，不能认证持卡人。

## 为什么不是另一个方案

| 替代方案 | 否决理由 |
|---|---|
| 读卡器装在机械臂末端 | ① 把五要素里的两个独立要素焊死；② 失败模式叠加——臂移动到读卡位失败再重试，在评委眼里就是"坏了"，拆开后读卡失败只是一次输入没进来；③ 机械臂本身尚未确认（`docs/HARDWARE.md` 记录 Star Arm 用途待确认），给未确认的负载再加射频 payload 是纯增风险 |
| 用 Passport 自己的 NFC 读牌 | 硬件上不可能。NTAG213 是被动标签，不是读卡器 |
| 语音唤名做主路径 | 现场几十个摊位同时说话，延迟 300–800ms 且会被误触发。协议第一要素是"认人"不是"听声" |
| 让名牌携带凭证 | 会改变认证模型；且牌可被拍照、复制，安全性比现在的 operator 会话更差 |

## 后果

换来：读卡与执行解耦，任一失败不牵连另一方；机械臂的选型风险不传导到认人链路；
接入路径不依赖任何未确认的硬件。

付出：多一个现场设备要自带（USB 读卡器），已列入 `docs/PLAN.md` 的待确认项；
少了一点"贴到机器上"的仪式感——这部分由名牌墙和回访演示补。

## 变更

无。
