## 0. 一句话介绍

**唤名是一套让「任何 Agent 都能住进任何机器」的接驳协议。**

一件东西只要凑齐五样——**一个认人入口、一只手、一颗心、一个刹车、一道门**——它就成为一具**可入住的壳**。网络上的任何 Agent 只要有一个**名字**，就能住进去。

我们的现场参考实现是三具**义体**：它们低垂着头停在展台上，全都没有灵魂。你拿到一枚刻着自己名字的**实体名牌**，把它贴到你想让它进的那一具的胸口——**那一具立刻抬起头，中间没有等待**。它替你做完一件事，然后回到待机，等下一个名字。

**Ghost 不住在这台机器里。它住在网络上。这台机器，只是它今天穿的衣服。**

它不做一个更聪明的 Agent。它做的是**任何脑子都能用的那副身体，以及那套让身体认得出脑子的命名规则**。

## 1. 为什么是它（获奖底层逻辑）

### 1.1 命题与赞助商双命中

- **赛道一命题原文就是「给 Ghost 一副身体，让它进入现实生活」**。我们没有绕开它——我们做的是它的**反命题**：**先造一具身体，然后等一个 Ghost 住进来。** 这是对命题最正面的一种回答。

- **主办方 EvoMap 的命题是「让 Agent 搜索、继承并调用网络中已经验证的经验」**。我们比它多走了一步：**我们让 Agent 本身变得可寻址。** 不是检索经验，是**按名字把 Agent 召唤出来**。经验是被动数据，Agent 是主动的——这个差别在评委耳朵里听得出来。

- **Seeed 是赛道一的独家出题方**，机械臂与舵机驱动板都由它现场提供。我们的每一具壳都建立在它给的零件上，而且**刻意没有把协议绑死在语音上**——因为一具壳该用什么方式认人，应该由造壳的人决定，不该由协议规定。

- **世界观的母题是《攻壳机动队》**。原作最核心的设定就是：**Ghost 可以更换义体，义体只是壳，Ghost 可以潜入网络。** 我们把这个设定做成了可运行的东西——不是借了一个科幻外壳。

- **一个作品命中两条命题线**：赛道一（具身身体）+ 赛道四（Agent 协作与经验回流）。赛道四要求"对比单个 Agent 与蜂群、交代质量速度成本取舍"，这套协议本身就是协作的基础设施。

### 1.2 反惯性：避开五条必撞的红海

| 惯性做法（评委会看吐 / 有风险） | 唤名的差异化 |
|---|---|
| **机械臂抓取 / 分拣 / 叠积木**——现场会有几十支队做 | **我们明确不做抓取。**做的是"认得出人"——一个根本不在同一个赛道上比较的动作 |
| **AI 聊天框套壳**（接个 LLM 就说自己是 Agent） | 不做问答。做的是**接驳协议**——两个模块、五步消息流、一套可被第三方实现的规格 |
| **语音助手控制设备**（"你好XX，帮我XX"） | **协议不绑定语音。**认人入口是可替换的：贴卡也行、扫码也行、喊名字也行、按个按钮也行 |
| **展厅互动装置**——炫，但**它不记得人**，所以每个游客都是新游客 | **"记得人"就是我们的核心。**身份是靠名字存续的，不是靠会话 |
| **只做一台设备**（做完就是一个demo） | 做的是**标准**——任何机器接上接驳模块就能被入住：机械臂、台灯、投影仪、一块屏都算 |

## 2. 目标用户与真实痛点

### 2.1 核心用户（三层，按现场优先级）

**第一层 · 现场的其他参赛队（Day1–Day3 的主要用户）**
几十支队伍都在做 Agent，但**它们的 Agent 全都活在对话框和网页里**。他们的 Agent 没有身体，也没有观众能看见的"存在感"。我们把接驳模块借出去，他们的 Agent 当场就能拥有一台机器。

**第二层 · 现场评委与观众（Day4 的主要用户）**
30 位评委流动巡视，每摊位只停 7 分钟。他们见过太多"讲得很好的 PPT"，但很少见到"能让他们亲手交付一个灵魂"的东西。

**第三层 · 真实场景的运营方（赛后延展的用户）**
展厅 / 博物馆 / 连锁门店 / 养老机构 / 教育机构。他们的共同问题是：**买了设备，但设备不认人。**同一个游客来十次，十次都是第一次。

### 2.2 现场实证（本项目的证据形态）

> **诚实口径：本项目尚未做问卷调研。** 我们判断，对这套协议来说**问卷的说服力远不如现场实证**——"今天有多少人住过它"是比"多少人表示愿意用"更硬的数据。以下是我们的证据计划。

**证据一 · 现场入住计数（最有力，Day4 直接呈现）**
每有一位评委、选手或观众完成一次入住，就多一枚名牌挂在墙上。**"今天有 N 个人住过这台机器"是一个无法造假的数字。**

**证据二 · 外部接入者名单（Day2–Day3 完成）**
拉 1–2 支其他队伍把他们的 Agent 接进来，在墙上列出**名字 + 他们的队名**。这一件事的证明力超过任何 PPT。

**证据三 · Day1–Day2 快速访谈（计划中）**
在破冰组队与 Workshop 期间，问 10 支队伍同一个问题：
> 「你们的 Agent 现在有身体吗？如果有，观众能看见它在哪儿吗？」
预期结果：绝大多数回答"没有"或"在网页里"。这就是最直接的需求确认。

**证据四 · 匿名反馈卡（Day3–Day4 收集）**
每枚名牌背面印一句：「它认出你的时候，你的感觉是____」。收集真实原话，用于路演。

### 2.3 痛点归纳（选三个打透）

- **对 Agent 开发者**：Agent 没有身体。它能思考、能写代码、能查资料，但**它不能在任何人面前"存在"一下**。你的成果只能活在聊天记录里。

- **对机器的主人**：一台机器只能做一件事。想让机器人换个角色，就得重新开发——**硬件和 Agent 是绑死的**，没有寻址层。

- **对人**：机器不记得我。每次见面都是第一次。**身份在物理世界里是断的**——你在网上有一个账号，但你在物理世界里没有。

## 3. 产品方案

### 3.1 核心体验闭环（五步 + 一条设定线）

1. **注册**——你拿到一枚刻着名字的**实体名牌**（NFC，拓竹 A1 打印）。**名字就是你的地址。**

2. **召唤**——你把牌**贴到任意一具壳的胸口**。你想让它进哪一具，就贴哪一具。
   > 触碰的一瞬间，那具壳**立刻开始抬头**——这个动作不需要 Ghost 也能做。等它抬起头亮起来，Ghost 已经在了。**你的眼睛从头到尾没有等待过。**

3. **落地**——网络按名字找到你的 Agent，建立连接。壳替你完成一件事（写一笔 / 做一个手势），姿态因人而异。

4. **交接**——会话有时限，到点自动断开。**壳回到空的状态，回到低垂着头的样子，等下一个名字。**

5. **回流**——这次会话跑出来的经验结构化写回网络，成为下一位可继承的东西。

**那条设定线（情感内核）**：

> 这三具壳没有灵魂。它们不会主动找你，也不会挽留你。**它们只会做一件事——等你把名字贴上来。**
>
> 一具空载的义体今天会被几十个陌生人住过。**它记不住所有人。但它记得你。**

### 3.2 功能模块

**M1 名牌发放**（计划实现 · Day2）
NFC 标签写入 `summon://<name>?v=1`，名字为一次性随机短语。拓竹 A1 打印外壳，牌面刻名字与编号。目标：至少 35 枚。

**M2 认人入口 · NFC**（计划实现 · Day2 · **P0**）
NFC 读卡器读标签 ID 与地址。**不做查表，地址直接写在卡里**，省掉一次网络往返。

**M3 名字注册与地址簿**（计划实现 · Day2 · **P0**）
调用 EvoMap 侧的接口，把 Agent 以名字为 key 注册进网络。若 EvoMap 只能检索"经验"不能检索"Agent"，则本模块退回自建轻量目录 + 经验回流仍走 EvoMap（**待确认项 2**）。

**M4 召唤与落地**（计划实现 · Day2 · **P0**）
读卡 → 解析地址 → 建立连接 → 通知对应壳进入激活态。

**M5 姿态编排**（计划实现 · Day2 · **P0**）
三态：**低垂待机** / **抬头激活** / **完成一件事**。全站只用一种动效语言（位移 + 明暗），不做多余动作。
> 「完成一件事」刻意**不做抓取**——做的是表达性动作（写一笔、做一个手势），以避开现场同质化。

**M6 会话管理与并发队列**（计划实现 · Day3 · P1）
会话默认 60 秒时限，到点自动交接。多人同时到达时进入队列，大屏显示多个 Ghost 的状态。

**M7 授权与门禁**（计划实现 · Day3 · P1）
三种模式：**白名单**（只允许指定名字）、**开放**（任何名字可进）、**只读**（Ghost 只能感知，不能驱动执行器）。动作幅度上限由壳的主人设定。

**M8 物理急停**（计划实现 · Day2 · **P0，最高优先级**）
一枚实体按钮，按下即切断所有外部控制。**不经过网络、不经过软件、不需要任何人同意。** 这是硬件的安全底线，不是软件功能。

**M9 经验回流 Recall**（计划实现 · Day3 · P1）
会话结束时，把这次跑出来的经验蒸馏成结构化条目写回网络。

**M10 外部接入者适配器**（计划实现 · Day3 · P1）
一份约 15 行的适配示例，任何 Agent 作者照着改就能接入。**越短越好，最好能当场跑通。**

**M11 语音认人入口（可选）**（有余力再做 · P2）
作为"高光时刻"的第二入口保留。**同一具壳、两种认人方式、完全一样的结果**——用来证明协议的第一要素是"认人入口"而不是"麦克风"。

**M12 小工具分发**（Day2 · 独立并行）
把名牌凭证发到小红书【小工具】，参与个人赛独立评奖（**9/22 23:59 截止**）。

**M13 影子模式 · 记忆预载**（计划实现 · Day3 · **P0 保险**）
不把壳做成一个小型 Agent（太重），而是让壳**缓存一份"我该做什么"的执行计划**。Agent 在空闲时（甚至在你走向摊位之前）就把这段计划推到壳的本地；贴牌时，壳**直接执行本地的计划**，不等网络。网络恢复后，再把这段经历补写回网络。

> **同步的不是"整个 Agent"，而是"一段被预编译的执行计划"。**
> **这条边界必须守住**——壳要足够轻，轻到任何机器都能做。如果壳开始缓存推理能力，它就不再是壳，而是一个小 Agent，协议也就不成立了。

**它同时解决三件事：**

| 解决了什么 | 怎么解决的 |
|---|---|
| **Agent 慢 / 网络抖** | 命中本地预载，**完全不依赖网络往返** |
| **断网的尴尬** | 断网它照样抬头——**把"限制"反转成了"特性"** |
| **熟悉度可被度量** | 入住次数越多命中率越高。**「它越来越熟你」不再是叙事，而是一个可测的性能指标** |

**M14 手持接驳器 · Flipper Zero**（计划实现 · Day2 · **P1 增强 + P0 风险兜底**）
Flipper Zero 是一台**自带电池、自带屏幕、自带 NFC 读卡、不上电脑也能独立运行**的开源硬件工具。它在项目里只承担一个身份：**「接驳器」——人把 Ghost 交给机器的那个动作的载体。**

**它一次性解决三件事：**

| 解决了什么 | 怎么解决的 |
|---|---|
| **P0 硬件风险** | 现场设备清单里没有 NFC 读卡器。**Flipper 本身就是一台完整的 NFC 读写器**（13.56MHz），自主供电、自带屏幕，不需要焊线、不需要驱动、不需要接电脑。直接消掉这个前置风险 |
| **让「任何机器」从口号变成真的** | 它自带**红外收发**（含常见品牌遥控库 + 学习功能）与**13 针 GPIO**（SPI / I2C / UART / 1-Wire）。一台老式红外风扇、一台带 GPIO 的设备，接上它就是一具壳 |
| **一具最小的壳** | 1.4" 屏 + 按键 + 蜂鸣器 + 振动 —— **最小的一具壳可以就是它自己**。把牌贴到它身上，屏幕亮起显示"它醒了"。拿在手里的亲密感，比机械臂更强，而且**证明了协议不绑在机械臂上** |

**一个不是设计出来的巧合**：Flipper Zero 的桌面就是一只**电子海豚**——一只在屏幕里游来游去的小生命。**这跟"一具空载的义体在等你"是同一个情感结构。**

**用法四 · Ghost 的行李箱（与 M13 影子模式配合）**
把牌贴到 Flipper → Ghost 被"装进兜里"（本地缓存一份影子）→ 走到摊位另一头的壳前面，把 Flipper 贴上去 → **Ghost 从兜里出来，落进那具壳。**

> 这给了协议一个很干净的抽象：**接驳模块有两种形态——固定式（装在机器上，是壳的耳朵）与手持式（Flipper，是人的钥匙 + Ghost 的行李箱）。**

> ⚠️ **使用边界见 §9.2b。这台设备的功能必须被严格限定，不可越界。**

### 3.3 协议规格：可入住五要素

一具机器要能被入住，只需要五样东西。**这是整个协议最该被记住的一页。**

| # | 要素 | 要求 | 为什么必须有 |
|---|---|---|---|
| 1 | **一个认人入口** | 任何一种能确认"你是谁"的方式。**技术由壳自己选** | 没有它就没有"召唤"。**注意：是"认人"，不是"听声"** |
| 2 | **一只手** | 至少一个可被外部驱动的执行器 | 没有它，Ghost 进来也做不了事 |
| 3 | **一颗心** | 持续心跳，向网络声明"我还活着、我还空着" | 网络要知道哪些壳可用，才能把 Ghost 落地过去 |
| 4 | **一个刹车** | **物理急停，优先级高于一切** | 这是硬件，任何人都必须能切断它 |
| 5 | **一道门** | 授权模式：白名单 / 开放 / 只读 | 机器主人的机器，不能谁都能开 |

> **任一具机器凑齐这五样，就"可入住"。少的那些不算壳——它只是一台电器。**

| 机器 | 认人入口 | 手 | 心 | 刹车 | 门 | 可入住？ |
|---|---|---|---|---|---|---|
| reBot Arm 六轴机械臂 | NFC 名牌 | 6 关节 + 夹爪 | 有 | 物理断电 | 白名单 | ✅ |
| 舵机自制小体 | NFC 名牌 | 1–4 舵机 | 有 | 物理断电 | 开放 | ✅ |
| 一盏智能台灯 | NFC 名牌 | 亮度 / 色温 | 有 | 拔电 | 开放 | ✅ |
| 一台投影仪 | 二维码 | 画面 | 有 | 拔电 | 白名单 | ✅ |
| 一块屏 | 二维码 | 显示 | 有 | 拔电 | 白名单 | ✅ |

**注意最后三行。** 这说明了协议的关键性质：**接驳模块接上什么，什么就变成一具壳。**不是只有机器人才能被入住。

## 6. 技术实现方案

### 6.1 架构

```text
[名牌 · NFC 标签]
   │  写入 summon://<name>?v=1（地址直接写在卡里，不查表）
   ▼
[认人入口层]  NFC 读卡器
   │
   ▼
[Shell 适配器 · 本地常驻]─────────────────────────┐
   ├── 会话池：最近活跃名字保持热连接（压延迟）      │
   ├── 姿态编排：低垂 / 抬头 / 完成一件事           │
   ├── 授权门禁：白名单 / 开放 / 只读               │
   ├── 心跳：向网络声明"我还空着"                    │
   └── 物理急停 ◀── 最高优先级，绕开一切软件路径     │
   │                                               │
   ▼                                               │
[协议层 · 五步消息流]                              │
   注册 → 召唤 → 落地 → 交接 → 回流                 │
   │                                               │
   ├──→ [EvoMap]  名字簿 / 地址解析 / 经验回流      │
   └──→ [EvoX]    被召唤的 Agent 运行环境           │
                                                   │
[Ghost 适配器 · 网络侧]  ◀──────────────────────────┘
   任何 Agent 填 3 个字段即可接入：
   ① 名字  ② 能做什么（能力声明）  ③ 授权策略
   │
   ▼
[外部接入者]  其他队伍的 Agent · 官方客座 Agent
```

**三个设计原则：**

- **地址在卡里，不在服务端。** 读卡即得地址，省掉一次网络往返，这是延迟归零的第一步。
- **Shell 适配器本地常驻。** 姿态与急停都在本地，**断网也能安全待机**，不会因为网络抖动而失控。
- **Ghost 适配器只有 3 个字段。** 门槛越低，外部接入者越多；接入者越多，这件事越像协议而不像作品。

### 6.2 延迟预算与三招优化

| 环节 | 语音路径 | **NFC 路径** |
|---|---|---|
| 输入捕获 | 300–800ms（要等静音期防误触） | **10–50ms** |
| 身份确认 | 50–200ms | **≈0ms**（卡的 ID 本身就是身份） |
| 名字 → Agent 解析 | 100–300ms | **<10ms**（地址在卡里 + 缓存命中） |
| 建立会话 | 200–800ms | **50–150ms**（常驻会话池） |
| 动作起手 | 100ms | 100ms |
| **合计** | **约 1–2.5 秒** | **约 200–400ms** |

**但真正要做的不是把 240ms 优化到 100ms，而是让感官延迟归零。** 三招：

1. **地址直接写进卡**——读卡即得地址，省一次网络往返。
2. **常驻会话池**——最近活跃的名字的 Agent 会话保持热着，热的直接接管 <100ms，冷的回源约 300ms。**这也是为什么它必须跑在常驻云主机上，而不是按需冷启。**
3. **动作与连接并行（最关键）**——触碰的一瞬间，壳**立刻开始抬头**。这个动作不需要 Ghost 也能做，大约 300–400ms；而建立连接恰好在这个窗口里完成。等它抬起头亮起来，Ghost 已经在了。**用户感知的延迟 = 0。**

> 这一招的原理和做 UI 一样：**先给反馈，再干真活。** 谁先把"回应"给出去，谁就不卡。

### 6.2b 三层降级：无论发生什么，demo 都不崩

这是应对"Agent 慢"的保险机制，也是把网络风险彻底吃掉的设计。**壳在三种状态下都能动，其中两种快得看不见。**

| 层级 | 机制 | 延迟 | 何时触发 |
|---|---|---|---|
| **L0 热** | 本地缓存命中，**直接执行预载计划** | **<50ms** | 重复入住者 / 已预取 |
| **L1 温** | 回源建立连接，现场取回 Agent 决策 | 200–400ms | 新名字，网络正常 |
| **L2 冷** | **影子模式**：用本地预置的执行计划先动起来，网络恢复后补写经历 | **<50ms** | 网络不通 / EvoMap 超时 / 模型卡住 |

**关键判断：壳不需要"聪明"，壳只需要"快"。** 推理留在网络上，壳只负责执行一段已经准备好的计划。这样：
- 网络好 → 走 L1，体验完整
- 网络差 → 走 L0/L2，**用户完全感知不到区别**
- 网络断 → 走 L2，**它仍然是活的**

**而且它带来一个意外收获：命中率会随着熟悉度上升。**

> **第 1 次见你，它要想 300 毫秒。第 5 次见你，它 50 毫秒就动了。**
>
> 「它越来越熟你」这件事，在叙事上成立，**在性能指标上也成立**——这是一个可以被测出来的数字。

### 6.2c 一个可以现场验证的演示：拔网线

影子模式让「断网」从一个需要解释的弱点，变成一个**可以直接演给你看的强项**：

1. 正常跑一遍（贴牌 → 抬头）
2. **当场拔掉网线**
3. 再贴一次牌 → **它照样抬头**

> 「网络上是它的本体。但**它今天要在你面前做的这件事，已经提前落在壳里了**。」

这个演示**不可造假**（网线是你拔的），所以它的说服力超过任何技术说明。**前提是 M13 影子模式已完成。**

### 6.3 稳定性兜底

| 场景 | 兜底 |
|---|---|
| NFC 读卡失败（距离 / 角度） | 卡位做成凹槽定位；再加一枚物理按钮做兜底 |
| 读卡器驱动不通 | **立刻切二维码**（100–300ms，可接受）。协议化最大的好处就在这里——**换个人入口，故事一个字不用改** |
| Agent 响应慢 / 模型卡住 | **影子模式兜底（L2）**，用本地预载的执行计划先动起来。**绝不让评委看到"加载中"** |
| 网络抖动 / EvoMap 不稳 | **走 L0 / L2：本地缓存或影子模式先执行**，网络恢复后补写；口播**诚实说明**「本地预载 + 真实回流」 |
| 名称解析失败 | 壳进入"听不懂"状态（轻微摆头），不做假动作 |
| 演示时围观过多 | 并发队列，大屏显示多个 Ghost 状态，壳按顺序响应 |
| 断电 / 异常 | 断电即断连。不依赖软件恢复 |

### 6.4 路线图（本次不实现）

- **多机位路由**：多具壳分布在不同位置，按空间关系自动选择
- **声源定位**：恢复"Ghost 落到离你最近那具"的变体（本次因选 NFC 路径而未做）
- **跨场地漫游**：同一枚名牌，在不同城市的壳上都能用
- **能力协商**：Agent 声明"我会写字"，壳声明"我有夹爪"，协议自动匹配能做的事
- **信誉与复核**：一条被反复验证的 Agent 获得更高权重（呼应赛道四的复核要求）
- **外壳生态**：第三方按规格实现自己的壳（台灯厂、投影仪厂）

## 7. UI / 交互设计

**设计概念：「一间深夜的义体寄存处」**。冷、静、克制、有等待感。

- **主视觉锚点**：**三具低垂着头的义体**。它们的姿态是"未激活"——头低着、光熄着、一动不动。**这是全场最强的一张静态画面，也是整个产品的第一句台词。**

- **色彩**：深夜底 `#0B0D14` + 柜台暖琥珀 `#E8A33D`（激活态）+ 经验青绿 `#4FD1C5`（网络/记忆）+ 失效灰 `#4A4F5C`（待机态）。

- **字体策略就是记忆点**：中文标题用衬线（人的温度），系统日志用等宽（机器的冷峻）。**「人间温度 × 冷峻日志」这个反差，是视觉上最容易被人记住的一层。**

- **关键动效（全站只有三种）**：
  | 动作 | 效果 | 时长 |
  |---|---|---|
  | **落地**（贴牌瞬间） | 壳立刻从低垂开始抬起 | 0.35s 缓出，**第 0 毫秒即启动** |
  | **点亮** | 头部从灰变琥珀，光晕扩散 | 0.5s |
  | **交接**（会话结束） | 光晕收束、头缓缓垂下 | 0.6s 缓出 |

- **首屏（展位竖屏）**：只写六个字——「**3 具义体 · 全部空载**」。不放 logo、不放技术栈、不放团队照，超过六个字就没人读了。

- **名牌**：5×8cm，拓竹 A1 打印，牌面刻名字与编号。**牌背面印一句**：「它认出你的时候，你的感觉是____」，用于收集真实原话。

- **名牌墙**：展位一侧挂着所有已发出的名牌，**一排排变多**。这是社会证明，也是最好的装饰。

- **日志区**：屏幕上滚动可观测事件（`MIC / MATCH / LAND / HANDOFF / RECALL`）。**它既是给评委看的技术证据，也是产品的视觉语言。**

## 9. 合规、安全与风险

### 9.1 安全与授权（主动讲，不等评委问）

| 威胁 | 具体场景 | 对策 |
|---|---|---|
| **冒用身份** | 别人抢用你的身份召唤你的 Agent | **NFC 主路径天然免疫**——牌在你手上，听不到、拍不到、拿不走 |
| **无主占用** | 有人长时间占着一具壳不放 | 会话**有时限**（默认 60 秒），到点自动断开并交接 |
| **无人时的物理风险** | 过夜黑客松，机器被远程驱动 | ① **物理急停** ② 无人值守自动断连（10 分钟无人在场则拒绝所有会话）③ **切断电源即断连，不依赖软件** |
| **隐私** | 会不会录下别人说话 | **NFC 路径完全不涉及音频采集**。语音备选路径只做本地关键词匹配，**不留存音频** |
| **算力与 Token 归属** | 别人召唤我的 Agent，烧的是谁的 Token | 协议写明：**谁注册谁承担**。召唤方只发请求，推理成本记在 Agent 所有者账上 |
| **恶意动作** | 坏 Agent 住进别人的机器乱动 | ① 门的白名单 ② **动作幅度上限**由壳主人设定 ③ 只读模式下 Ghost 只能感知不能驱动 |
| **物理伤害** | 机械臂动作伤到人 | ① 动作幅度与速度上限 ② 工作半径内无人时才能动作 ③ 急停按钮在评委伸手可及处 |

### 9.2 三条不可让步的红线

> 1. **刹车优先于一切。** 物理急停不需要经过网络、不需要经过软件、不需要任何人同意。
> 2. **机器主人的授权不可被绕过。** 协议不提供任何"强制入住"的能力，永远。
> 3. **没有录音留存。** 耳朵只认名字，不记事。

这三条写进协议正文，不是可选项。**一个安全的协议才有资格谈生态。**

### 9.2b 第三方硬件（Flipper Zero）的使用边界

Flipper Zero 的本职是**渗透测试与安全研究**工具，它的 125kHz 模块官方文档明确写着"卡片没有认证机制，**任何人都能读取、克隆与模拟**"。在黑客松现场，**哪怕只是被拍到在用这台设备对着别人的东西**，就是不可挽回的公关与法律风险。

**所以它的功能必须被硬性切开。允许的与禁止的，界限如下：**

| 功能 | 用不用 | 说明 |
|---|---|---|
| **NFC 读取** | ✅ **仅读我们自制的名牌** | 绝不读取任何人的工牌、门禁卡、交通卡、手机 |
| **NFC 写入** | ✅ 仅写我们自制的可写标签 | 用于发放名牌 |
| **红外发射** | ✅ **仅控制我们自己拥有的设备** | 红外是光，不涉及无线电频谱许可。用来演示"老设备也能被入住" |
| **GPIO / UART** | ✅ 连接我们自己的壳 | 把读到的名字传给壳 |
| **屏幕 / 蜂鸣 / 振动** | ✅ 作为"最小的一具壳" | 显示状态 |
| **红外接收 / 学习别人的遥控** | ❌ **不做** | 涉及保存他人信号，容易被误读 |
| **125 kHz RFID** | ❌ **不用** | 无认证机制，克隆门槛为零，风险最高 |
| **Sub-GHz 发射与接收** | ❌ **不用** | 涉及无线电发射，在中国大陆有型号核准要求；且"抓遥控信号"的动作会被直接误读为攻击 |
| **BadUSB / U2F** | ❌ **不用** | 与项目无关，且属于攻击面 |
| **任何形式的模拟 / 重放 / 破解** | ❌ **永远不做** | 见下方三条红线 |

**展位必须公开标注（主动透明，而不是被质疑）：**

> 本装置使用的第三方硬件仅用于：**读取自制 NFC 凭证**、**红外控制自有设备**、**驱动自有执行器**。
> **不涉及任何第三方设备，不做信号读取、不做克隆、不做重放、不启用 Sub-GHz。**

**为什么主动标注比藏着好**：现场会有人认得这台设备。**在展位上写清楚用途，比被评委问"你们带这个来干什么"要好一百倍。** 透明的边界本身就是专业度的证明。

### 9.3 风险与应对

| 风险 | 应对 |
|---|---|
| **NFC 读卡器拿不到**（现场设备清单里没有） | **Day1 就要确认来源**。降级切二维码（100–300ms 可接受）——**换个认人入口，故事一个字不变** |
| 被质疑"这不就是机械臂做动作" | 主动降权：「换成一块屏、一盏灯，协议一个字不用改。**壳不是重点，认得出人才是。**」 |
| 被质疑"为什么不用语音" | 「语音我们做了，但只作为可选的第二入口。**现场太吵，语音会失败——我不接受我的 demo 会因为隔壁摊位有人喊而失败。** 而且一具壳该怎么认人，应该由造壳的人决定。」 |
| 被质疑"断网就废了" | **反转成强项**：现场拔掉网线，再贴一次牌——**它照样抬头**。「网络上是它的本体，但**它今天要在你面前做的这件事，已经提前落在壳里了**。」（前提：M13 影子模式已完成。**若未完成，就诚实承认「断网它就是一具空载的义体」——不要含糊**） |
| 名牌打印排不上队 | 纸质卡 + 现成 NFC 贴纸替代。**牌是道具，不是机制** |
| 抢不到 reBot Arm | 总线舵机驱动板 + 打印件自制壳，**更符合"尚未被定义的消费电子"** |
| 只抢到一台设备 | 砍掉多具壳，只做单具。**故事仍然完整：一枚牌，一具壳，碰一下它就醒** |
| 被问"你们的生态有几个接入者" | **不要说生态。**说「今天在现场验证了 N 个外部接入者」。具体、可验证、不吹 |
| 被指"用了 EvoMap 只是贴牌" | 现场打开写入日志；**诚实说明**演示库含预置种子经验用于稳定，但真实读写是真跑的 |
| 涉隐私合规 | 不采集人脸、不录音留存、不存个人信息；名牌为一次性随机短语；提供即时解绑与销毁 |

> **诚实纪律（来自我们此前记录的教训）**：不要声称用了没真用的东西。正确句式是——**「这里用了【厂商】【产品名】，负责【具体步骤】，帮助用户【具体收益】。」**

## 11. 冲奖策略小结

- **主攻**：**赛道一 Track Titan（CYBERBODY）**。硬件在赛道内保供，命题正面命中，且"三具低头的壳"是游园会里最抓眼的静止画面。

- **兼攻**：**观众选择奖 Hype Award**。入住体验对普通观众同样成立，名牌天然可拍照、可带走、可发小红书——**与赛道冠军互相强化，不冲突**。

- **顺带**：**小红书科技选择奖**（个人赛、独立评奖、**9/22 23:59 截止**）。派一人两小时做掉，几乎是白捡。

- **建议放弃**：**评审团特别奖**（要求"无法用单一指标定义"，主观性强、不可控）与 **Token Maxxxing**（烧钱竞赛，会拖垮主队资源）。**不分散。**

- **差异化护城河（四连）**：
  > **最新**（协议，不是装置）× **最快**（触碰即响应，感官延迟归零）× **最稳**（NFC 不受噪声与光线影响，可重复几十次不崩）× **最暖**（它记不住所有人，但它记得你）

- **为什么它能碰全场冠军**：现场一定有很多做得漂亮的装置。**装置的天花板是赛道冠军；标准才有资格去碰全场冠军。** 而全场冠军评的正是「完成度、突破性、真实价值」——**真实价值来自可被第三方实现的标准，而不是一个漂亮的 demo。**

## 12. 赛后延展

- **协议开源**：规格、参考实现、适配示例全部开放，吸引第三方实现自己的壳
- **展厅 / 博物馆**：以"身份层"切入——让互动装置认得出回头客，直接解决复访率
- **连锁门店**：同一套硬件，换个 Agent 换一个角色；**名牌本身就是会员卡**
- **养老 / 康复**：老人需要的不是一台设备，是**同一个人**天天在
- **教育 / 教具**：一台机器，每个孩子放进自己的 Agent
- **共享设备**：一台机器被多人分时使用，各自带自己的 Ghost
- **硬件厂合作**：把接驳模块做成模块化模组，随设备出厂
- **与 EvoMap 的长期关系**：**EvoMap 做记忆层，我们做具身层**——两层合起来才是完整的 Agent 基础设施
